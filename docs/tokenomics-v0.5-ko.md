이 문서는 제5안 원고를 Markdown으로 옮긴 상세 정책이다. 아래의 권고·제안 표현은 원고의 채택 및 실행 구분을 보존한다. 문서 게시를 잠금·다중서명·발행 권한 변경 완료로 해석하지 않는다.

SHAH CAT은 고양이 캐릭터와 게임 및 커뮤니티를 연결하는 프로젝트다. 본 제5안은 기존 배분 수량을 유지하면서 운영자와 투자자의 역할을 구분하고, 해제 일정·게임 보상·공동 재무 통제를 하나의 기준으로 정리한다. 게임의 실제 이용과 운영 현금을 먼저 검증하고 토큰 공급은 승인된 범위에서 단계적으로 집행한다.

### 이번 제5안의 권고 결론

기존 초기 3인 배정 합계 50%를 운영 창립자 333,333,334 SHAH와 초기 전략투자자 166,666,666 SHAH로 분류한다. 개인별 배분 수량은 바꾸지 않는다. 운영 창립자는 12개월 대기 후 24회 해제, 박원은 10% 즉시 자유와 나머지 90%를 대기 없이 24회 해제하는 단일 권고안을 제시한다. 투자자 역할을 반영해 12개월 대기를 없앤 설계다.

최종 협의안은 작성 완료된 권고안이라는 뜻이다. 총량 10억 개와 초기 3인 합계 5억 개 및 개인별 목표 배분은 기존 합의 기준이며, 역할 재분류·해제 조건·나머지 배분·집행 규정은 3인의 서면 채택이 필요하다. 현재 투자금 입금·계약·잠금·배포 완료를 의미하지 않는다. 모든 수량은 SHAH 단위다.

### 투자자의 자유권과 제한 물량

박원에게는 16,666,666.6 SHAH를 T0부터 자유롭게 이전 가능한 물량으로 두고, 149,999,999.4 SHAH는 매월 6,249,999.975 SHAH씩 24회 해제하도록 제안한다. 12개월 강제 대기는 두지 않는다. 자유·해제 물량의 이전과 매도에 운영팀의 추가 건별 승인을 요구하지 않는 것을 기본으로 한다.

처분 자유는 즉시 현금 회수나 원금 보장이 아니다. 실제 매도 가능 금액은 시장 유동성에 따라 달라진다. 투자자 조건과 실제 자금 지원의 성격·금액·시기·추가 의무는 별도 합의한다. 투자자 배정의 명칭 자체로 출자 완료를 증명하거나 신규 자금 조달 약정을 만들지 않는다. 기존 배정의 회수나 삭감도 이 문서로 지시하지 않는다.

### 기준일과 회차 경계

T0는 3인이 동일 기준일에 동의하고 각 제한 물량의 실제 예치를 확인한 UTC 시각이다. Tn은 T0로부터 n개월째의 확정 시각이다. 월말·윤년 처리 규칙과 T0부터 T36까지 모든 시각을 배포 전에 고정한다. 최초 공개 유통일 TGE는 별도로 기록한다. TGE가 늦으면 그때까지 이미 해제된 투자자 물량도 유통 계획에 반영한다.

운영자에게는 T12에서 일괄 지급하지 않고 T13에 첫 회차를 해제한다. 이후 T36에 마지막 회차가 끝난다. 본안은 월별 분할형이며 초 단위 연속 선형 해제와 다르다. 실제 프로그램은 이 월별 경계를 지원해야 한다. 연속 방식으로 변경하려면 일정과 공시를 수정하고 다시 동의한다.

### 정확한 지급 산식

배포 대상 Mint의 decimals가 9로 확인되면 제한 배분량을 10의 9제곱으로 곱한 정수 A로 관리한다. 24회 중 완료 회차 k의 누적 해제량은 floor(A × k ÷ 24)이며, 신규 청구 가능량은 누적 해제량에서 이미 청구한 양을 뺀 값이다. 즉시 자유 물량은 A에서 제외한다. 마지막 회차는 잔여 최소 단위까지 전량 정산한다.

성재와 동원의 각 월평균은 약 6,944,444.458333333 SHAH다. 이는 반복소수의 근사 표시이며 첫 회차는 각각 6,944,444.458333333 SHAH다. 중간 곱을 포함해 충분한 범위의 정수를 사용하고 부동소수점으로 지급량을 계산하지 않는다. decimals가 다르면 최소 단위 산식을 재검증한다.

### 잠금 증빙과 사후 변경

개인 지갑으로 보낸 토큰은 별도 예치 없이 잠기지 않는다. 프로그램 주소·수혜자·예치량·시작과 종료 시각·관리자 및 취소 권한을 확인한다. 서면 제한과 기술적 잠금을 구분한다. 합의와 수혜자 동의 및 기술적 가능성을 확인하지 않고 기존 권리를 일방적으로 변경하지 않는다.

### 최초 유통량은 실행 예산으로 산정

최초 유통량은 미정으로 둔다. 풀에 실제 예치할 SHAH, 이전 가능한 투자자 물량, 외부에 지급한 자유 물량을 합산하고 중복을 제거한다. T0부터 TGE까지 이미 해제된 양도 포함한다. 단순 준비금 내부 이동은 시장 공급으로 세지 않는다. 공시 유통량은 기준 시각과 비유통 지갑 및 제외 사유를 함께 제시한다.

TGE가 T0와 같다고 가정하고 풀 150M과 커뮤니티·마케팅 30M을 즉시 공급하면, 투자자 자유 물량까지 합쳐 196,666,666.6 SHAH로 약 19.6667%다. 이는 비교 계산이며 채택 수치가 아니다. 커뮤니티·마케팅 30M은 커뮤니티 배정 50M에서 차감한다는 가정이며 잔여는 20M이다.

유동성 150M은 전체 한도이며 최초 전량 예치 의무가 아니다. 18%나 7~12%를 일률 기준으로 채택하지 않는다. 공개 후 공급 상한 확대는 3인 전원 동의와 시행 7일 전 공지를 제안한다. 용도·수량·대상·유통량 영향을 공개하며 사후에 자유 물량을 잠금으로 바꾸지 않는다.

## 3 SHAH와 CHURU의 게임 경제

| 항목 | SHAH | CHURU |
| --- | --- | --- |
| 성격 | Solana 기반 토큰 | 오프체인 게임 포인트 |
| 역할 | 선택형 콘텐츠와 검증 기여 보상 | 플레이와 아이템 및 편의 기능 |
| 전환 관계 | 고정 환전 의무 없음 | 현금·SHAH 청구권 없음 |
| 공급 관리 | 기존 배정 예산에서 지급 | 획득 한도와 소모처 관리 |

### 기본 게임 순환

미션 수행 → 서버 검증 → CHURU 획득 → 먹이·집 꾸미기·탐색·수색 등 게임 행동에 사용 → 포인트 소모로 연결한다. 일반 플레이는 SHAH 구매나 지갑 연결 없이 이용할 수 있게 설계한다. 택배·선물·실종 고양이 수색·입양 등은 기존 게임 구상에 따른 사용처 후보이며 출시 완료 기능으로 소개하지 않는다.

CHURU와 SHAH의 고정 교환비를 두지 않는다. CHURU 보유만으로 현금이나 SHAH를 지급할 의무가 발생하지 않는다. 지급·차감은 요청 ID별로 한 번만 처리하고 잔액과 사유를 원장에 남긴다. 일일 획득 한도·아이템 가격·환불 규칙은 게임 테스트로 정한다.

### 시범 SHAH 보상

첫 6개월은 월 최대 500,000 SHAH, 누적 최대 3,000,000 SHAH로 제안한다. 보상 배정 100M의 3%, 전체 1B의 0.3%다. 지급 의무나 수익 약정이 아니며 검증된 기여와 승인 예산 안에서 정산한다. 매월 미사용분은 같은 보상 준비금에 남기고 다음 달 한도에 자동 가산하지 않는다.

개인 지급량은 min(B × s ÷ S, 0.02 × B)를 최소 단위로 내림한 값이다. B는 월 승인 예산, s는 개인 검증 점수, S는 전체 검증 점수다. 점수는 사전 공개한 비음수 기준으로 정한다. S가 0이면 지급하지 않는다. 상한 때문에 남은 물량은 재분배하지 않는다.

B가 500,000이고 S가 10,000, s가 100이면 5,000 SHAH다. 한 사람이 전체 점수를 받더라도 개인 상한은 10,000 SHAH이며 490,000은 준비금에 남긴다. 한 지갑이 한 사람임을 보장하지 않으므로 계정·행동·지갑 패턴을 함께 심사하고 이의신청을 마친 뒤 지급한다.

### 사용처와 수익화의 단계

SHAH 사용처는 선택형 외형 아이템, 커뮤니티 한정 콘텐츠, 검증된 창작·개발 기여 보상을 우선 검토한다. 수익화 후보는 선택형 콘텐츠와 실제 계약한 제휴다. 게임 경제가 SHAH 신규 구매에만 의존하는 구조를 피하고 비보상 이용자의 재방문과 소비를 먼저 검증한다.

CHURU 소모는 SHAH 소각이 아니다. 토큰 결제로 받은 SHAH는 재무 지갑 유입으로 기록하며 현금 전환 전에는 운영 현금으로 계산하지 않는다. 거래세·고정 수익·의무 바이백을 기본안에 두지 않는다. P2P·NFT·유료 추첨·현금성 보상은 별도 출시 검토 대상이다.

### 지급 오류와 경제 불균형 대응

CHURU 지급이 소모를 2개월 연속 초과하면서 1인당 잔액도 증가하면 획득과 소모처를 재검토한다. 부정 이용·취약점·정산 오류가 발견되면 신규 지급을 보류하고 원인·영향·재개 조건을 공개한다. 정상 이용자의 기존 자산을 일괄 삭제하거나 약정한 권리를 임의 변경하지 않는다.

## 4 Treasury 승인과 집행 규정

### 예산과 승인 정족수

Treasury는 공동 준비금과 운영자금이다. 비상 예비금 5%와 구분한다. 월 예산은 목적·자산·수량·수수료 상한·집행 기간별로 정하고 3인 전원이 동의한다. 승인된 예산 내 일반 지출은 성재·동원·박원 중 서로 다른 2명이 승인한다. 요청 분할로 한도나 승인 조건을 회피하지 않는다.

본인 또는 관련자 지급은 이해관계자를 정책 승인 정족수에서 제외하고 나머지 2인이 승인한다. 이해관계 없는 승인자 2명을 확보하지 못하면 일반 절차로 집행하지 않는다. 기술적 2인 서명이 이해상충 규정 준수를 자동으로 보장하지 않는다. 특정 두 명의 반복 집행은 월간 대조로 점검한다.

배분·해제 조건, 서명자·승인 임계값, 배정 목적, 예산 밖 집행과 예비금 인출은 3인 전원 동의를 요구하는 것으로 제안한다. 수혜자 권리 변경은 당사자 동의와 기술적 가능성까지 확인한다. 긴급 사유도 추가 지출의 단독 승인 근거가 되지 않는다. 승인 불능 상황에서는 신규 재량 집행을 보류한다.

### 사용 범위와 사적 사용 금지

승인 가능한 지출은 서버·인프라·개발·보안·법률 검토·실제 제휴와 비상 대응 비용이다. 상장 관련 지출은 상대방과 계약 및 예산을 별도 검토한다. 합의된 정당한 용역·급여는 증빙과 이해상충 심사를 거쳐 지급할 수 있다. 개인 거래 손실 보전, 사적 투자, 증빙 없는 인출과 부정 거래는 허용하지 않는다.

| 단계 | 필수 기록 | 핵심 통제 |
| --- | --- | --- |
| 요청 | 요청 ID·목적·예산 항목·증빙<br>네트워크·Mint·수량·수령 주소 | 원화 참고 평가와 시각 기록 |
| 승인 | 동일 버전에 대한 독립 승인 2명 | 내용 변경 시 기존 승인 무효 |
| 집행 | 전송한 거래 서명과 성공 여부 | 중복 집행 금지 |
| 대조 및 공개 | 장부·잔액·영수증·승인자 대조 | 정정 이력과 월간 공개 |

### 백엔드 구현 명세

상태는 작성 → 제출 → 승인 완료 → 전송 중 → 체인 확인 → 장부 대조 완료다. 반려·취소·기한 만료·실패·상태 확인 대기를 구분한다. 승인 버전에 주소·자산·수량·네트워크·수수료 상한과 전체 거래 명령을 묶는다. 권한 이전·위임 등 승인 목적 밖 명령을 검사한다.

전송 결과가 불명확하면 거래 서명과 요청 상태를 조회해 중복 지급을 막는다. 원본 원장은 삭제하지 않고 정정 사유와 연결 기록을 추가한다. 소스 코드 보안 패치는 허용하며 재무 권한 변경은 특별 승인을 받는다. 서명자 개인키를 서버에 모으지 않는다. 이 명세는 코드 구현이나 다중서명 배포 완료를 뜻하지 않는다.

다중서명 도입 전에는 서면 승인·분리 보관·대조를 적용하고 한 사람이 기술적으로 전송 가능한 상태인지 명시한다. 집행액·목적·승인자·거래 서명·준비금 잔액을 매월 공개한다. 운영 현금, 토큰 수량과 LP 예치는 구분한다.

## 5 유동성과 권한 및 공개 지표

### 운영 현금과 유동성 예산

실제 보유 원화·SOL·USDC 등 결제 가능한 자산으로 운영비를 산정한다. 초기 SOL 30만 원 상당 투입 방향은 실행 기준점이며 입금 완료로 단정하지 않는다. 개인 자금은 출자·대여·무상 지원 중 성격을 합의한다. 토큰의 미실현 평가액을 운영비 확보로 계산하지 않는다.

네트워크 비용과 서버 등 필수 비용, 비상 잔액을 먼저 계산한 뒤 LP 예산을 정한다. 최초 SHAH 예치량은 상대 자산 예산·초기 가격·풀 구조로 산정한다. 단순 균형 예치에서는 SHAH 수량 = 상대 자산 금액 ÷ SHAH당 가격이며 기준 통화를 같게 한다. 집중 유동성은 가격 범위를 포함해 별도 계산한다.

예정 거래별 가격 영향·수수료·제공자 손실을 검토한다. 상대 자산 예산이 부족하면 LP 공급을 보류할 수 있다. LP 지분이나 포지션의 소유 주소·인출 권한·잠금 여부와 종료일을 공개한다. LP 잠금은 운영자·투자자 잠금과 별개다. 거래량 조작과 자기 거래는 성과에서 제외한다.

### 공급 권한과 기술 검증

공식 네트워크·Mint·Token Program·decimals와 실제 공급량을 확인한다. Mint Authority와 Freeze Authority는 각각 보유자 또는 폐기 상태를 공개하고 메타데이터·확장·관리자 권한도 별도로 기록한다. Devnet 이력으로 Mainnet 상태를 대신하지 않는다.

정책상 기준 총량은 10억 개다. 발행 권한이 남아 있으면 추가 발행의 기술적 차단 완료로 발표하지 않는다. 해당 권한을 None으로 폐기하면 영구적으로 제거되므로 배분·배포·운영 요건을 확인한 후 별도 실행하고 거래 증빙을 공개한다. 실제 소각은 토큰 소각 명령과 공급 감소로 검증한다.

## 6 스트레스 점검과 채택 절차

이 페이지의 수치는 계산 예시이며 실제 이용자·매출·시세·비용 예측이 아니다. 실제 장부와 플레이 데이터로 교체한다.

| 점검 상황 | 예시와 대응 |
| --- | --- |
| 이용자 증가 | 월 예산 500,000을 균등 배분하면<br>100명은 5,000·1,000명은 500·10,000명은 50 SHAH<br>참여자 증가로 총예산을 자동 증액하지 않음 |
| 보상 매도 | 월 지급분의 25%·50%·100% 매도는<br>125,000·250,000·500,000 SHAH<br>실제 풀 구조와 잔액으로 가격 영향을 계산 |
| 현금 부족 | 30만 원으로 월 순지출 3만 원이면 10개월<br>10만 원이면 3개월인 단순 계산<br>LP 예치 자산은 운영 현금과 분리 |

매도량에 초기 가격을 곱한 값은 실제 매도 가능 금액이 아니다. 투자자 자유 물량과 월 해제량까지 합쳐 매도 상황을 점검한다. 운영 현금 여력이 예상 순지출 3개월분 미만이면 신규 확장과 보상 확대를 재검토하고 기존 계약상 의무와 필수 보안 비용을 우선 점검한다. 순지출이 0 이하이면 나눗셈 대신 잔액과 필수 고정비를 직접 표시한다.

### 이번 제5안에서 끝낸 정책 정리

역할 구분은 기존 개인 수량을 유지하는 재분류로 정리했다. 투자자의 12개월 대기를 없애고 10% 자유와 90% 24회 해제안을 권고한다. 잘못된 개인·전체 월 해제량과 겹치는 기간 표를 교정했다. 출처 없는 시장 권장 비율과 준수 점수, 소스 코드 변경 금지는 제외하고 승인 버전·정정 이력·실행 증빙을 기준으로 삼았다.

정책 원고는 제5안으로 통합한다. 팀 동의와 실제 배포값은 남아 있는 실행 항목이다. 본 문서는 원금·고정 수익·상장·가격 유지 또는 회사 지분을 보장하지 않는다. 토큰 판매·유료 추첨·현금성 보상·P2P 출시는 적용 법률·세무·이용자 보호를 별도로 검토한다. 미출시 기능과 계획된 제휴를 현재 서비스로 표시하지 않는다.

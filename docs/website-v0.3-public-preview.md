# SHAH CAT Web v0.3 — 정적 공개 미리보기 배포본 (2026-10-31)

## 현재 결과

이번 단계는 **공식 홈페이지 정적 파일을 안전하게 따로 빌드·검증하는 단계**입니다. 사이트를 인터넷에 공개하거나 도메인에 연결한 단계가 아닙니다. 기존 Devnet 대시보드와 Treasury 운영 기능 및 정책은 변경하지 않습니다.

- 개발자 로컬 화면: `http://127.0.0.1:4173/site/`
- 로컬 대시보드: `http://127.0.0.1:4173/`
- 로컬 Treasury 승인 기록: `http://127.0.0.1:4173/treasury.html`
- CI 검증 미리보기: PR #102의 **Actions → SHAH CAT CI → Public static site bundle (artifact only)** 실행 결과에서 내려받는 ZIP

현재 공개 홈페이지 주소/도메인은 미정입니다. 빌드 통과와 상용 서비스 준비·법률 검토 완료는 다릅니다.

## 생성 방법 (Node.js 20+)

프로젝트 폴더 루트에서 실행:

```cmd
node scripts\build-public-site.mjs
```

생성 결과: `dist/public-site/`

허용된 파일은 딱 네 개입니다.

| 파일 | 목적 |
| --- | --- |
| `index.html` | 공개용 프로젝트 소개 및 필수 시험 단계 고지 |
| `site.css` | 반응형 스타일 |
| `site.js` | 공개용 메뉴·복사 등 브라우저 동작 |
| `logo.png` | SHAH CAT 공식 로고 |

**로컬용 링크는 공개본에 포함되지 않습니다.** 소스에서는 `LOCAL_WORKSPACE_*` 표시로 한정된 영역을 구분하며, 빌드 과정에서 이 영역을 삭제합니다. 허용되지 않은 파일이 추가되거나 경계 표시가 빠지거나, 공개 HTML의 주소/링크가 잘못되면 빌드가 실패합니다. 빌드 결과는 `dist/`에만 생성되며 Git에는 자동 추가되지 않습니다.

## 자동화와 공개 범위

GitHub Actions의 `public-site-preview` 작업은 위 네 파일을 검증 후 **Artifacts로 보관**합니다. 공개 웹사이트 게시, GitHub Pages 활성화, DNS 변경, 자산 송금, 계약 승인, 관리자 서비스 노출은 수행하지 않습니다.

정적 파일은 공개 가능한 정보만 포함합니다. `dashboard/server.mjs`, `treasury.html`, Treasury 설정/원장, 지갑 개인키, RPC 제어 API 또는 Node 런타임은 패키지에 포함하지 않습니다.

**중요:** 공개 서비스 운영에서는 관리자 기능을 다른 서버로 분리하고 정식 인증·인가·로그·백업·보안 검토를 마련해야 합니다. 이 빌드 도구는 서버 자체를 보호하는 방화벽이나 접근제어를 대신하지 않습니다. 기존 Node 서버를 `0.0.0.0`이나 역방향 프록시로 공개하지 마세요.

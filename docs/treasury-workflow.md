# SHAH CAT Treasury 정책 승인 — 1단계

기준: 토크노믹스 v0.5. SHAH Devnet 전용 로컬 도구이며, 요청·수정·메시지 서명 검증·원장 보관을 구현한다. **온체인 다중서명 배포와 토큰 집행은 미구현**이다. `policy_approved`는 이 원장의 정책 동의 완료일 뿐 지급·거래 서명·잔액 확보·법적 계약 체결을 증명하지 않는다.

## 지금 사용할 수 있는 기능

| 항목 | 구현 범위 |
| --- | --- |
| 운영 주소 | 공개 주소 설정 파일로 Treasury와 서명자 3명을 명시. 개인키는 입력받지 않음 |
| 월 예산 | 한 UTC 월 안의 기간, 목적, SHAH 한도, SOL 수수료 합계 상한을 전원 승인 |
| 일반 지출 | 전원 승인된 예산에 연결. 독립된 등록 지갑 2개의 메시지 서명 필요 |
| 이해상충 | 등록 서명자 주소 수령 시 자동 제외. 관련자는 수동 신고. 나머지 2명이 필요 |
| 특별 지출·예비금 | 3인 전원 승인. 이해상충으로 전원 독립 승인이 불가능하면 차단 |
| 내용 수정 | 승인 대기 요청만 수정. 새 버전·nonce 생성, 이전 승인 무효. 완료·반려 요청 수정 불가 |
| 예산 한도 | 동일 예산에 연결된 승인 완료 요청의 SHAH·수수료 누적액 검사. 동시 승인도 직렬 처리 |
| 승인 증빙 | 원장 ID·설정 해시·요청 ID·버전·nonce·결정·지갑·자산·주소·수량·기간·수수료·근거를 메시지에 묶어 서버에서 Ed25519 검증 |
| 원장 | 로컬 추가 기록 방식 JSONL, 쓰기 후 fsync, 프로세스 간 쓰기 잠금, 재시작 시 해시 연결·승인 서명과 상태 전이 검사 |
| 내보내기 | 요청과 서명을 포함한 원장 JSON 다운로드. 외부 공개는 별도 검토 |

## Windows에서 실행

최신 `main` 코드를 받은 뒤 `dashboard` 폴더에서 명령 프롬프트를 연다. Node.js 20 이상을 사용한다. 서명 UI는 현재 **Phantom 브라우저 확장**을 지원한다.

1. 공개 주소 설정 파일을 만든다.

```cmd
copy treasury-config.example.json local.treasury.config.json
notepad local.treasury.config.json
```

2. `REPLACE_WITH_...` 네 곳을 실제 확인한 Solana **공개 주소**로 바꾼다. Treasury와 3인 주소는 모두 달라야 한다. 예시 파일의 자리표시자는 의도적으로 실행 불가능하다. 서버에 개인키·시드·지갑 JSON을 넣지 않는다.
3. 같은 명령 프롬프트에서 실행한다.

```cmd
set TREASURY_CONFIG=local.treasury.config.json
node server.mjs
```

4. `http://127.0.0.1:4173`의 **Treasury 승인** 링크 또는 `http://127.0.0.1:4173/treasury.html`을 연다. 설정을 하지 않으면 조회 화면만 열리고 요청·승인은 비활성이다.

PowerShell에서는 환경변수 명령을 `$env:TREASURY_CONFIG="local.treasury.config.json"`으로 바꾼다. 파일 경로는 서버를 실행한 폴더 기준이다. 주소 설정을 바꾸면 서버를 다시 시작해야 한다.

## 시험 절차

1. 각 운영자가 본인 역할에 등록된 공개 주소인지 별도 확인한다. 지갑 서명은 해당 키의 통제를 증명하며 실명·역할 확인을 대신하지 않는다. 서로 다른 세 주소가 세 사람의 독립 통제임을 자동 증명하지 않는다.
2. 해당 월의 시작일·종료일, 목적, 근거, SHAH 예산과 SOL 수수료 합계 상한을 작성한다. 종료일은 그날 **UTC 00:00부터 제외**한다. 예: 10월 예산은 `2026-10-01`부터 `2026-11-01`까지다.
3. **검토 → Phantom 연결 → 서명할 내용 확인 → 내용에 동의하고 메시지 서명**을 진행한다. 각 운영자는 본인 지갑으로 반복한다. 계정·결정이 바뀌면 메시지를 다시 확인해야 한다.
4. 예산이 `정책 승인 완료 · 미집행`이 되면 일반 지출을 작성하고 해당 예산을 선택한다. 관련자 지급 여부를 표시한다. 동일 절차로 독립 지갑 2개가 승인한다.
5. 원장을 내려받아 요청·버전·서명자·수량·상태를 확인한다. 화면과 원장에는 집행 기능이 꺼져 있다고 표시된다.

하나의 공용 PC에서 각자 본인 Phantom 계정으로 서명하는 로컬 운영을 전제로 한다. 여러 PC를 사용하면 각각 별도 원장이 생기며 승인이 합쳐지지 않는다. 외부 공개·프록시·LAN 바인딩은 지원하지 않는다. 다중 사용자 서비스가 필요하면 인증·권한·공유 DB·배포 설계를 먼저 추가한다.

## 원장과 복구

- 원장은 `dashboard/.treasury-data/events.jsonl`에 저장되고 Git에서 제외된다. `*.treasury.config.json`도 제외된다. 실제 주소 설정과 원장을 커밋하지 않는다.
- 요청·버전·승인·반려 이벤트를 추가한다. 삭제·승인 철회·승인 완료 요청 취소·예약 해제 API는 없다. 잘못된 완료 요청은 실행하지 않고 별도 검토한다.
- 승인 완료된 지출은 만료되어도 예산 예약을 유지한다. 외부에서 이미 집행됐는지 알 수 없으므로 자동으로 재사용하지 않는다. 이 도구가 외부 지출이나 서로 다른 예산 간 분할을 자동 추적하지는 않는다. 월 예산의 중복 편성은 운영자가 전원 승인 전에 검토한다.
- 정상 종료는 `Ctrl+C`로 한다. 같은 원장에 두 서버가 쓰지 못하도록 `.lock` 파일을 사용한다. 강제 종료 후 잠금이 남으면 기록된 PID의 서버가 실제로 종료됐는지 확인하고 원장 전체를 백업한 다음 `events.jsonl.lock`만 제거한다. 실행 중인 서버의 잠금을 지우지 않는다.
- 해시 연결은 파일 손상·일부 변경 탐지용이다. 외부 공증이나 관리자에 대한 변조 불가능성을 제공하지 않는다. 복구용 원본 원장은 서버 종료 후 별도로 백업한다. 다운로드 JSON은 검토용이며 자동 복원 포맷이 아니다.
- 기존 원장은 설정 해시에 묶인다. 운영 주소·Treasury가 바뀌면 기존 원장을 그대로 이어 쓰지 못한다. 주소 변경은 특별 승인 절차와 별도 원장 이관 검토 대상이다. 오류를 없애기 위해 기존 원장을 삭제하거나 임의 수정하지 않는다.
- 서버는 같은 컴퓨터의 로컬 사용자에게 요청 작성·대기 요청 수정 권한을 준다. 정책 승인은 등록 키의 서명이 있어야 한다. Host·Origin·JSON 요청을 검사하며 원장 쓰기 실패 이후에는 추가 쓰기를 막는다.
- 증빙에는 공개 가능한 참조만 넣고 비밀번호·신분증·개인키를 넣지 않는다. 내보내기에는 사업 목적과 공개 키·메시지 서명이 포함되므로 월간 커뮤니티 공시는 검토된 요약으로 따로 작성한다.

## 남은 집행 단계

실제 사용 전에는 온체인 다중서명 프로그램·Vault 주소·서명자·임계값을 확인하고, 승인된 **전체 거래 명령과 정확한 거래 버전**에 대한 공동서명을 연결해야 한다. 그다음 전송 중·확인 대기·실패·체인 확인·장부 대조 상태, TXID 중복 방지, 불명확 결과 재조회, 영수증·월간 공개를 구현한다. 이 단계의 메시지 승인을 거래 서명으로 재사용하지 않는다.

현재는 SOL·USDC 운영비 지급, LP 조작, 권한 변경 명령을 만들지 않는다. 특별 지출·예비금 요청도 SHAH 정책 승인 기록에 한정된다. 실제 잔액과 네트워크 상태는 기존 대시보드에서 별도로 조회한다. 공급 정책과 베스팅 조건은 변경하지 않는다.

## 검증

```cmd
node --test dashboard/*.test.mjs
```

저장소 루트에서 실행한다. 테스트는 생성한 임시 Ed25519 키와 로컬 HTTP 서버를 사용한다. 실제 운영자 키·실제 Phantom 확장·온체인 다중서명을 검증한 결과가 아니다.

기술 참고: [Phantom message signing](https://docs.phantom.com/solana/signing-a-message), [Node.js crypto.verify](https://nodejs.org/api/crypto.html#cryptoverifyalgorithm-data-key-signature-callback). 구현은 Node 기본 모듈을 사용하고 새 런타임 패키지를 추가하지 않는다.
